## コードの修正方法
# phaseごとに、作業をすすめ、クリーンビルト（pio run）を行うこと。
# 同時に行わずにフェーズごとにステップバイステップで進めてください。

## 修正phase

# phase1: ESP32標準APIへの準拠とハードウェア操作の最適化
  レジスタを直接叩くような不透明なハックは避け、Arduino Core for ESP32 や ESP-IDF の提供する標準API（Wire, pinMode, attachInterruptなど）を正しく使用するように修正してください。

# phase2: 割り込みハンドラーの適切なカプセル化
  グローバル空間を汚染するような無秩序な割り込みハンドラの実装を避け、HAL（ハードウェア抽象化レイヤー）内または適切なクラス内にコールバックとして隠蔽（attachInterrupt等を利用）するように修正してください。

# phase3: デバッグライトの配置最適化
  デバッグライトは、機能を呼び出す側（Caller）ではなく、実際に処理が行われる呼ばれるメソッド側（Callee）の内部で行うように修正してください。これによりコードの見通しを良くします。

# phase4: マジックナンバーの排除
  コード内に直接埋め込まれたマジックナンバー（ピン番号、遅延時間、I2Cアドレスなど）がないか確認し、あれば `AppConst.hpp` などの共通ヘッダで `#define` や `constexpr` を使って一元管理するように修正してください。
