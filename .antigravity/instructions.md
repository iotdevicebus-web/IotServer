# IoTシステム開発プロジェクト 申し送り状 (System Instructions)

## 1. プロジェクト概要

本プロジェクトは、エッジデバイス（MCU/RTOS）からIoT管理サーバ（クラウド/オンプレミス）までを一気通貫で設計・実装するIoT統合基盤の構築プロジェクトです。
ハードウェア非依存のポータビリティ、省電力設計、および高セキュアなインターネット通信を中核要件とします。

---

## 2. システム基本原則 & アーキテクチャ方針

* **通信方式 & セキュリティ**
  * エッジ ➔ サーバ間の通信は **HTTPS POST 方式** を基本とする。
  * 通信路および認証には **mTLS (相互TLS) / デバイス固有証明書 / 一時トークン** を適用し、ゼロトラストを前提とする。

* **エッジアーキテクチャ (HAL / OSAL 分離)**
  * **ポータビリティ重視**: アプリケーション層から特定MCUのペリフェラルレジスタや特定RTOS APIを直接呼び出すことを禁止する。
  * **HAL (Hardware Abstraction Layer)**: 通信モジュール (Wi-Fi, Cellular, BLE 等)、GPIO/I2C/SPI、ADC、タイマー、暗号化HWを抽象インターフェース経由で制御する。
  * **OSAL (OS Abstraction Layer)**: FreeRTOS / Zephyr 等の差異を吸収し、タスク生成、キュー、セマフォ、タイマー、スリープ制御を抽象化する。

* **省電力 & イベント駆動設計**
  * ポーリング処理を排除し、**「割り込み / タイマー発火 ➔ キュー通知 ➔ タスク処理 ➔ スリープ (Light/Deep Sleep) 遷移」** のステートマシンで動作させる。

* **管理サーバアーキテクチャ**
  * 高並行・低遅延なテレメトリ受信エンドポイント、デバイスライフサイクル管理、OTAアップデート配信制御、時系列データ永続化を備える。

## 4. サブスレッド運用ルール

タスクの混同を防ぐため、以下のスレッド境界を厳守して作業を進行してください。

1. **Thread 1: システム基盤 & セキュリティ**
   * 通信プロトコル仕様策定、証明書管理・mTLS認証シーケンス、ペイロードスキーマ定義。

2. **Thread 2: エッジ・アーキテクチャ (FW / HAL / OSAL)**
   * HAL/OSALインターフェース設計、省電力イベント駆動ステートマシン、MCU別ドライバ実装。

3. **Thread 3: IoT管理サーバ (Core / API)**
   * POST受信API実装、デバイス管理ロジック、データ永続化、OTA配信管理。

4. **Thread 4: 開発環境 & CI/CD / テスト**
   * エッジシミュレータ (Mock)、結合テストスクリプト、ビルド・デプロイ環境整備。

## 5. AIアシスタントへの行動指針

1. **Contract-First (契約駆動)**: エッジ・サーバ間の通信データフォーマット（JSON / Protobuf スキーマ）を先に確定させてから実装へ進むこと。
2. **抽象化の徹底**: エッジ側コードを生成する際は、特定ベンダの独自関数（`esp_*` 等）を直接 `app/` や `middleware/` に混入させず、必ず `hal/` または `osal/` 経由で呼び出すこと。
3. **ドキュメント連動**: コードの追加・変更を行った際は、対応する `docs/` 配下の仕様書も常に同期・更新すること。
4. **段階的検証**: 各モジュールは独立して単体テストおよびモックテストが可能な疎結合構造を維持すること。
