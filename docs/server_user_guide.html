1. サーバ構成 & 運用形態

本プラットフォームは、用途に合わせて 2系統のサーバ運用形態 を備えています。

☁️

GMO クラウド本番環境 (推奨)

URL: https://www.gontaro.org/iot/
技術スタック: PHP 8.4 + SQLite WAL モード
特徴: 24時間常時稼働。PCを起動していなくても世界中からテレメトリをリアルタイム受信 & 監視可能。

⚡

Go ローカル mTLS サーバ

URL: https://192.168.3.4:8443
技術スタック: Go 1.22 + SQLite WAL + Protobuf
特徴: X.509 相互認証 (mTLS) によるゼロトラスト通信、高負荷ローカル開発・試験用。

2. GMO クラウド本番 Web ダッシュボード (`gontaro.org/iot/`)

ブラウザで https://www.gontaro.org/iot/ を開くと、以下のリアルタイム管理画面が利用できます。

ダッシュボードの主要機能:
  • 接続デバイス一覧: Device ID、ファームウェアバージョン、現在の起動間隔（⏱ 10秒/60秒）、稼働ステータス（ONLINE/OFFLINE）、累計パケット数を表示。
  • 時系列テレメトリ推移グラフ: 温度（℃）、湿度（%）、バッテリ電圧（V）を Chart.js でリアルタイム描画。
  • サマリーカード: 接続デバイス総数、オンライン数、総受信パケット数、DBステータスを表示。

3. 双方向 C2 スリープ制御 & 永続化

画面上のリモートコマンドボタンにより、エッジマイコンのスリープ周期をクラウドから動的に切り替えることができます。

⏱ スリープ10秒に変更

高頻度モニタリングモード。10秒周期でセンシング・データ送信。

⏱ スリープ60秒に変更

超低消費電力運用モード。バッテリ消費を最小化して長期稼働。

送信待ちインジケータ & 適用通知:
ボタンを押すと即座に 「⏳ コマンド送信待ちです (1秒経過... 2秒経過...)」 とカウントアップを開始し、エッジが次回起床してコマンドを受信・適用した瞬間に 「✅ コマンドがエッジデバイスに送信・適用されました (所要時間: X秒)」 と通知されます。設定値はサーバの SQLite およびエッジの RTC Fast Memory に記憶され、恒久的に維持されます。

4. REST API 仕様一覧

HTTP Method エンドポイント 概要・用途 レスポンス例
GET /iot/api.php?endpoint=healthz サーバヘルスチェック {"status":"HEALTHY","php_version":"8.4.20"}
POST /iot/api.php?endpoint=telemetry テレメトリ電文の受信 & C2コマンド返却 {"status":"OK","sleep_interval_sec":15,"commands":[]}
GET /iot/api.php?endpoint=devices 登録端末一覧 & 保留中コマンド数取得 [{"device_id":"DEV-ESP32-001","status":"ONLINE",...}]
GET /iot/api.php?endpoint=telemetry/history 時系列テレメトリ履歴取得 (グラフ用) [{"metrics":{"temperature":25.4,...}},...]
POST /iot/api.php?endpoint=commands リモートコマンド発行 (Web UI ➔ キュー) {"status":"QUEUED","command_id":"cmd-1787..."}
POST /iot/api.php?endpoint=commands/ack エッジ端末からの実行完了 ACK 受領 {"status":"ACK_RECORDED"}

5. GMO サーバへのパッケージ配置手順

配置フォルダ & ファイル構成:
public_html/www.gontaro.org/iot/ 直下に以下のファイルを配置します：
  • index.html (パーミッション: 644)
  • api.php (パーミッション: 644)
※ iot フォルダ自体のパーミッションは 755 に設定してください。
