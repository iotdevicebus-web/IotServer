OFFICIAL PROTOCOL SPECIFICATION

エッジ・クラウド間 通信プロトコル仕様書 (詳細版)

仕様書番号: PROTO-SPEC-2026-V1 バージョン: 1.0.0 (Final) 適用対象: ESP32-S3, STM32, IoT Server 更新日: 2026-08-17

1. プロトコルスタック概要

本プラットフォームにおけるエッジマイコンとインターネット管理サーバ間の通信レイヤ構成です。標準的な TCP/IP スタック上に TLS 1.3 相互認証 (mTLS) を適用し、アプリケーション層では Protocol Buffers v3 を採用して極限までオーバーヘッドを削減しています。

階層 (OSI / TCP-IP) 採用プロトコル / 技術 用途・詳細仕様
L7: アプリケーション層 Protocol Buffers v3 / JSON バイナリシリアライズ (Wire Type: 0, 2, 5). ペイロード圧縮率 約81%
L7: アプリケーション転送 HTTP/1.1 (Keep-Alive 対応) RESTful API エンドポイント (POST / GET)
L5-L6: 暗号・認証層 TLS 1.3 / 1.2 (mTLS 相互認証) X.509 デバイス固有証明書, ECDSA-P256 / RSA-2048, HSM 連携
L4: トランスポート層 TCP (Port: 8443) 高信頼ストリーム転送
L3: ネットワーク層 IPv4 / IPv6 IP ルーティング (SAN: 192.168.3.4 等)
L1-L2: データリンク・物理層 Wi-Fi (802.11 b/g/n) / LTE-M / Ethernet 無線通信モデム (Wi-Fi Station / Cellular Cat-M1)

2. mTLS セキュア接続ハンドシェイク

本システムは「ゼロトラスト」モデルに基づき、サーバだけでなくエッジマイコン側も固有のクライアント証明書を提示して相互に身元を証明します。

sequenceDiagram autonumber participant Edge as Edge Device (ESP32-S3) participant SE as Secure Element (HSM) participant Server as IoT Server (:8443) Edge->>Server: 1. ClientHello (TLS 1.3, Supported Ciphers) Server-->>Edge: 2. ServerHello, Server Certificate, CertificateRequest Note over Edge: サーバ証明書を Root CA で検証 Edge->>SE: 3. I2C: CertificateVerify 用 Hash (SHA-256) 署名要求 SE-->>Edge: 4. ECDSA-P256 署名データ (64 Bytes) Note over SE: 秘密鍵はチップ外に一切出ない Edge->>Server: 5. Client Certificate, CertificateVerify (HSM署名), Finished Note over Server: クライアント証明書の CN/SAN と DeviceID を照合 Server-->>Edge: 6. Handshake Finished (mTLS 確立完了)
セキュリティ検査ルール (サーバ側):
サーバはハンドシェイク完了後、クライアント証明書の Subject CommonName (CN) または SAN (Subject Alternative Name) を抽出し、送信ペイロード内の device_id と完全一致するか検証します。不一致の場合は直ちに 403 Forbidden で切断します。

3. Protocol Buffers ワイヤーフォーマット (バイナリ構造)

エッジ側では外部ライブラリ（nanopb等）に依存せず、ピュア C99 で Wire Type を直接エンコードします。動的メモリ確保（malloc）は一切行いません。

3.1 Wire Type 定義

Wire Type 種別 適用フィールド データ構造
0 Varint timestamp, seq_no, boot_count, uptime, interval_sec (定期起動間隔) 7ビットごとに分割、最上位ビット(MSB)で継続フラグ
2 Length-delimited device_id, firmware_version, state 長さ (Varint) + UTF-8 バイト列
5 32-bit (Fixed32) temperature, humidity, battery_voltage IEEE 754 float32 (リトルエンディアン 4バイト)

3.2 フィールドタグ (Field Tag) のバイナリ構造 (MetricsData)

Field 1 (0x0D)temperature (FIXED32)
Field 2 (0x15)humidity (FIXED32)
Field 3 (0x1D)battery_voltage (FIXED32)
Field 4 (0x20)battery_pct (VARINT)
Field 5 (0x28)rssi (VARINT)
Field 6 (0x30)interval_sec (VARINT)

4. テレメトリ送信プロトコル (POST /api/v1/telemetry)

エッジデバイスがスリープから目覚めた際に、測定データおよび現在の定期起動間隔をサーバへ送信する主トランザクションです。

4.1 HTTP リクエスト仕様

POST /api/v1/telemetry HTTP/1.1
Host: 192.168.3.4:8443
User-Agent: IoT-Edge/1.0.0 (ESP32-S3)
Content-Type: application/x-protobuf
Content-Length: 81
Connection: close

[... 81 Bytes of Protocol Buffers Binary Payload including interval_sec ...]

4.2 HTTP レスポンス仕様 (通常時 200 OK)

HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 148
Date: Mon, 17 Aug 2026 14:00:00 GMT

{
  "status": "OK",
  "message": "Telemetry accepted",
  "server_time": 1786952324,
  "sleep_interval_sec": 10,
  "commands": []
}

5. 双方向 C2 ピギーバック制御仕様

スリープ駆動マイコンは常時着信（待受）が不可能なため、「エッジからのテレメトリ POST に対する HTTP レスポンスにリモートコマンドを相乗り（ピギーバック）させて配信」 します。

sequenceDiagram autonumber actor Admin as 管理者 participant Server as IoT Server participant Edge as ESP32-S3 Admin->>Server: 1. POST /api/v1/commands (例: CONFIG_UPDATE, sleep=10s) Note over Server: commands テーブルに status='PENDING' で保存 Note over Edge: スリープ満了・目覚めて送信 Edge->>Server: 2. POST /api/v1/telemetry (70B) Server-->>Edge: 3. 200 OK (コマンドを含めて返信) Note over Edge: コマンドを実行し、スリープ時間を10秒に変更 Edge->>Server: 4. POST /api/v1/commands/ack (Result: SUCCESS) Server-->>Edge: 5. 200 OK (ACK受理) Note over Edge: 10秒間のスリープに移行

5.1 コマンド相乗り時の HTTP レスポンス例

HTTP/1.1 200 OK
Content-Type: application/json

{
  "status": "OK",
  "message": "Telemetry accepted",
  "sleep_interval_sec": 10,
  "commands": [
    {
      "command_id": "cmd-1786942080986903700",
      "action": "CONFIG_UPDATE",
      "payload": "{\"sleep_interval_sec\":10}"
    }
  ]
}

5.2 サポートするリモートコマンド一覧

Action 名 パラメータ (Payload) エッジ側の動作
CONFIG_UPDATE {"sleep_interval_sec": 10} Deep Sleep 待機時間を指定秒数に即時書き換え
REBOOT {} ACK 返信後に esp_restart() を実行して再起動
SELF_TEST {} I2C センサ、バッテリ ADC、暗号モジュールを自己診断
OTA_TRIGGER {"version": "1.1.0"} 指定バージョンの OTA ダウンロードシーケンスを開始

6. コマンド実行結果 ACK プロトコル (POST /api/v1/commands/ack)

エッジデバイスはコマンドを実行後、直ちに実行結果ステータスをサーバに報告します。

6.1 ACK リクエスト例

POST /api/v1/commands/ack HTTP/1.1
Host: 192.168.3.4:8443
Content-Type: application/json

{
  "command_id": "cmd-1786942080986903700",
  "device_id": "DEV-ESP32-001",
  "status": "SUCCESS",
  "result_payload": "{\"applied_sleep_interval\":10}",
  "executed_at": 1786942082
}

7. 暗号化 OTA 更新プロトコル (GET /api/v1/ota/download/{ver})

sequenceDiagram autonumber participant Edge as ESP32-S3 participant Server as IoT Server Edge->>Server: 1. POST /api/v1/telemetry Server-->>Edge: 2. 200 OK {"ota_available": true, "new_version": "1.1.0", "sha256": "b0bc03..."} Edge->>Server: 3. 8. タイムアウト & オフライン再送制御 (8MB PSRAM / SRAM バッファ)

山間部や地下など、一時的な電波断（圏外）が発生してもデータが欠損しないよう、8MB Octal PSRAM 上に最大 10,000件（約 1.5MB）、内部 SRAM 上に 32〜64件のリングバッファ を保持します。

状態 / イベント タイムアウト値 エッジステートマシンの挙動
Wi-Fi 接続試行 最大 15 秒 (30回試行) 接続不能時は Wi-Fi を即時 OFF ➔ データを 8MB PSRAM バッファに Push ➔ スリープ
TLS ハンドシェイク 最大 3 秒 エラー時は接続をクローズ ➔ データを 8MB PSRAM バッファに Push ➔ スリープ
HTTP POST 応答待ち 最大 3 秒 200 OK 未達時はデータを 8MB PSRAM バッファに Push ➔ スリープ
次回通信成功時 - 最新データ送信後、8MB PSRAM に蓄積された過去データ (最大10,000件) を古い順に自動フラッシュ送信

9. エラーコード & 復旧マトリクス

HTTP Status エラー理由 エッジデバイス側の対応アクション
200 OK 正常完了 通常どおり Deep Sleep に移行。
400 Bad Request ペイロード破損 / 不正スキーマ 送信データを破棄し、次回センシングから再試行。
401 Unauthorized クライアント証明書未提示 セキュアエレメント・証明書設定を確認して再起動。
403 Forbidden 証明書 CN と DeviceID の不一致 なりすまし検知。通信を停止しエラーログを記録。
500 / 503 サーバ側一時障害 / DB ビジー データをバッファに退避し、指数バックオフで再送。
